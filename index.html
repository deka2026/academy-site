학습개요

바이브 코딩이 무엇인지 큰 그림부터 이해해요. 개념을 읽은 뒤 '실습시작' 메뉴에서 한 단계씩 실습합니다

⚠ 시작 전 준비물: 클로드 유료 계정(Pro 이상)
이 과정은 내 클로드에 프롬프트를 붙여넣으며 진행하고, 5단계부터는 Claude Code를 씁니다. Claude Code는 무료 계정으로는 쓸 수 없고, 무료 계정은 대화 한도도 금방 차서 실습이 끊겨요.
claude.ai에서 가입한 뒤 Pro 요금제로 시작하세요. 필요해지면 Max로 올리면 됩니다. 결제 정보는 본인이 직접 입력하세요(강사·AI에게 맡기지 않기).

바이브 코딩 한눈에 보기 (1부 · 전체 지도)

웹사이트가 만들어지는 큰 그림을 "지도 한 장"으로 먼저 이해해요. 순서는 딱 4단계입니다.

STEP 1. 도구 세팅

클로드 코드 — AI와 대화하며 코드를 만드는 작업 도구

STEP 2. 프론트엔드

HTML·CSS·JS — 눈에 보이는 화면

STEP 3. 백엔드

Supabase — 데이터 저장·처리

STEP 4. 배포

Cloudflare Pages — 인터넷에 공개

그리고 이 흐름 전체를 받쳐주는 것이 Git(내 컴퓨터의 세이브 파일)과 GitHub(인터넷 창고)예요. 아래 카드를 하나씩 눌러 읽어보세요.

1도구 — 두뇌와 손발▾

AI 코딩 도구는 두 부분으로 나눠 이해하면 쉬워요.

  • 두뇌(LLM): ChatGPT, Gemini, Claude 같은 거대 언어 모델. 생각을 담당해요.
  • 손발(코딩 에이전트): 실제로 파일을 만들고 코드를 고치는 도구. 우리는 클로드 코드를 써요.

도구는 이렇게 진화해왔어요

  • 터미널: 검은 명령어 창으로 컴퓨터를 제어 (구식)
  • VS Code: 코드 편집기에서 파일을 보며 작업
  • Cursor AI: 편집기에 LLM을 통합
  • 클로드 코드 PC판: 터미널·편집기 없이 단독 실행 (최신)

유료 구독이 필요해요(이 페이지 맨 위 준비물 상자 참고). 전문가에게 개발을 맡기는 비용에 비하면 훨씬 저렴하고, Pro로 시작해 필요해지면 Max로 올리면 돼요.

실습시작 메뉴의 5단계(Claude Code 설치)에서 직접 설치해봐요.
2설치 3종 세트 — 도구 + 세이브 파일 + 인터넷 창고▾

바이브 코딩을 시작하려면 세 가지만 설치하면 돼요.

  • ① 클로드 코드: AI 코딩 작업 도구
  • ② Git: 코드가 바뀔 때마다 저장·복원할 수 있는 게임 세이브 파일 같은 도구. Mac은 기본 설치, Windows는 git-scm.com에서 다운로드해요.
  • ③ GitHub: Git 기록을 보관하는 인터넷 창고. 가입 후 클로드 코드와 연결해요.
주의! GitHub는 자동 저장이 아니에요. "올려 줘"라고 직접 명령해야 인터넷 창고에 올라가요.

실습시작 메뉴의 2단계(Git)·8단계(GitHub 저장소)에서 하나씩 실습해요.

3사이트의 두 얼굴 — 프론트엔드와 백엔드▾

웹사이트는 시계에 비유하면 쉽게 이해돼요.

  • 프론트엔드 = 시계판: 초침·분침·숫자처럼 눈에 보이는 화면. HTML·CSS·JS, React 같은 기술을 써요.
  • 백엔드 = 태엽: 알람·타이머처럼 화면 뒤에서 데이터를 처리하는 장치. 서버·데이터베이스·API가 여기 속해요.

회원가입이나 게시판 같은 기능을 만들려면 백엔드가 꼭 필요해요. 백엔드는 복잡하지만 개념만이라도 이해해두면, 나중에 AI에게 요청할 때 훨씬 정확한 결과를 얻을 수 있어요.

4프론트엔드 — '규모'만 전달하면 스택은 AI가 정해요▾

어떤 언어·기술로 만들지 고민할 필요 없어요. AI에게 만들려는 것의 규모만 정확히 알려주면 돼요.

간단한 한 페이지짜리 [우리 단체] 소개 사이트를 만들어 줘. 어떤 스택과 어떤 언어로 제작할지도 미리 알려 줘.

이 프롬프트는 나중에 사이트를 만들 때 쓰는 예시예요. 실습시작 15단계는 내 위키를 인터넷에 공개하는 것까지만 다룹니다.

왜 '규모'가 중요할까요?

  • 언어와 구성마다 장단점이 달라요.
  • 작은 스택으로 큰 서비스를 만들면, 방문자가 몰릴 때 사이트가 멈출 수 있어요.
  • 그래서 처음 설계할 때부터 규모에 맞추는 것이 매우 중요해요.
5백엔드 — 복잡한 과정을 대신하는 두 매니저▾

① Supabase — 데이터 매니저

서버 빌리기, 데이터 저장, 프로그램 설치를 한 번에 처리해주는 서비스예요. 회원가입·게시판·신청서처럼 데이터를 저장하는 기능을 만들 때 씁니다.

  • 큰 흐름: 가입 → 프로젝트 만들기(지역은 서울) → 프로젝트 URL과 공개(anon) 키를 클로드 코드에 알려주면 연결 코드와 표 생성문을 만들어줘요 → SQL Editor에서 실행
  • 보안: 공개 키라도 환경변수 파일에 저장해서 노출을 막아요.

실습시작 15단계에는 Supabase 단계가 없어요. 위키를 공개하는 데는 필요 없고, 나중에 저장 기능이 필요할 때 아래 프롬프트를 내 클로드에 붙여넣으면 돼요.

나는 컴퓨터 초보자야. 내 사이트에 [신청서/게시판] 기능을 넣고 싶어서 Supabase를 처음 써 보려고 해. 가입부터 프로젝트 만들기(지역 서울), 프로젝트 URL과 공개(anon) 키를 안전하게 보관하는 법, 표(테이블) 하나 만들어서 사이트에서 저장한 값이 표에 나타나는지 확인하는 것까지 한 번에 한 가지씩 알려줘. 키는 환경변수 파일에 두고 코드에 직접 쓰지 않게 해 줘.

② Cloudflare Pages — 배포 매니저

내 컴퓨터에 있는 사이트를 인터넷에 올려주는 서비스예요. 유튜브의 '업로드' 버튼과 같아요.

  • GitHub 계정으로 연결 → 저장소 선택 → Deploy → 내 사이트 주소 발급
  • 내 컴퓨터가 꺼져 있어도 24시간 운영돼요.
  • GitHub에 수정본을 올리면 사이트도 자동으로 업데이트돼요.
실습시작 메뉴의 9단계(Cloudflare Pages 배포)에서 직접 해봐요.
1부 3줄 요약
① 도구는 클로드 코드 하나면 충분해요.
② 프론트엔드는 규모만 전달하면 언어·스택은 AI가 정해줘요.
③ 백엔드는 Supabase(데이터) + Cloudflare Pages(배포) 두 매니저에게 맡겨요.

원문: 바이브 코딩의 개요 (1부)

바이브 코딩 깊이 보기 (2부 · 하네스, 나만의 AI 작업장)

1부가 "좋은 도구 고르기"였다면, 2부는 "좋은 작업장 만들기"예요. 명령 한 번의 '딸깍'만으로는 세 가지 벽에 부딪혀요: 매번 처음부터(AI가 과거 맥락을 기억 못 함), 신뢰성 부족(그럴듯한 거짓 생성), 기능 제한(외부 데이터 연결 불가). 이 벽을 넘는 장치가 하네스입니다.

1MD — AI가 매번 자동으로 읽는 헌법▾

.md 형식의 지시문 파일이에요. CLAUDE.md, AGENTS.md, GEMINI.md처럼 도구마다 이름이 달라요. AI가 작업을 시작할 때마다 자동으로 읽기 때문에 "헌법"이라고 불러요.

  • 실제 사용 예: "거짓말 금지", "데이터 우선" 같은 레드라인을 기록해둬요.
실습시작 메뉴의 6단계(CLAUDE.md 작성)에서 직접 만들어봐요.
2스킬 — 반복 작업을 레시피 카드로▾

자주 반복하는 작업을 이름 붙은 절차로 저장해두는 거예요. 요리 레시피 카드처럼, 이름만 부르면 정해진 순서대로 실행돼요.

  • 실제 사용 예: '배포', '지원사업', '위키 발행' 같은 스킬을 만들어두고 한 마디로 실행해요.
실습시작 메뉴의 12단계(스킬 만들기)에서 직접 만들어봐요.
3커넥트(MCP) — 외부 서비스를 잇는 표준 콘센트▾

AI를 외부 서비스에 연결하는 표준 규격이에요. 어떤 기기든 꽂을 수 있는 콘센트처럼, 한 가지 방식으로 여러 서비스를 연결해요.

  • 실제 사용 예: Supabase, Gmail, 캘린더, 텔레그램 등을 AI에 연결해서 "메일 확인해줘" 같은 요청이 가능해져요.
실습시작 메뉴의 13단계(커넥트 연결)에서 GitHub를 직접 연결해봐요.
4API — 프로그램끼리 정보를 주고받는 창구▾

프로그램들이 서로 정보를 교환하는 공식 창구예요. 민감한 키(열쇠)는 반드시 환경변수에 따로 저장해서 노출을 막아요.

  • 실제 사용 예: 법령·날씨·지도 API를 연결해서 AI가 실시간 정보를 활용하게 해요.
  • Anthropic API 키는 내가 만든 프로그램에서 클로드를 부를 때 쓰는 열쇠예요. Claude Code를 Pro·Max 구독으로 로그인해 쓰면 키가 없어도 돼요. 오히려 키를 환경변수에 영구 등록하면 Claude Code가 구독 대신 API 종량 요금으로 동작하니 주의하세요.
실습시작 메뉴의 7단계(API 키 설정)는 선택 단계예요. 구독으로 쓰는 분은 건너뛰어도 됩니다.
5에이전트 — 작업별 전담 AI 나누기▾

하나의 AI에게 모든 걸 시키는 대신, 특정 작업을 전담하는 AI 여럿으로 나누는 방식이에요.

  • Maker(생성) ↔ Checker(검증) 역할을 분리하면 결과의 신뢰도가 올라가요.
  • 실제 사용 예: 코드 담당, 문서 담당, 배포 담당 에이전트를 따로 두고 협업시켜요.

6루프 — 그리고 무인 루프를 돌리지 않는 이유▾

자동 실행(타이머), 격리 작업대, 스킬, 커넥트(MCP), 전담 에이전트, 디스크 기억 — 이 6가지 부품이 모이면 스스로 도는 자동 작업장(루프)이 완성돼요. 그런데 마지막 조각인 "완전 무인 재귀"는 일부러 넣지 않아요.

무인 재귀의 세 함정

  • 검증 붕괴: 아무도 안 본 결과가 계속 쌓여요.

연대지능 연결하기

개인 위키와 연대지능 위키를 연결하여 현장 지식을 공유합니다

연대지능 위키 저장소: deka2026/solidarity-intelligence-wiki
활동가 각자의 Quartz 위키에서 작성한 문서를 연대지능 위키에 반영 요청으로 올리면, 검수를 거쳐 공동 지식이 돼요.

개인 위키 → 연대지능 위키 연결 구조

1. 내 위키

Obsidian + Quartz로 운영하는 개인 위키. 현장기록, 메모, 학습 노트를 자유롭게 쌓습니다.

2. 정제 & 분류

개인 노트 중 공유할 만한 것을 4종 문서 유형(개념, 현장기록, 사용법, 사례연구)으로 정리합니다.

3. 반영 요청

정리된 문서를 연대지능 위키 저장소에 내 공간에 복사 → 반영 요청으로 올려요. Claude Code로 자동화할 수 있어요.

4. 검수 & 최종 반영

검토자가 지식 분류 5가지 질문으로 검수해요. 통과하면 최종 반영되어 연대지능 위키에 게시됩니다.

시작하기: 연대지능 위키 셋업

아래 프롬프트를 Claude Code에 붙여넣으면 연대지능 위키 저장소를 내 공간에 복사하고 개인 위키와 연결하는 설정을 자동으로 진행해요.

연대지능 위키에 기여하고 싶어. 다음을 순서대로 해줘: 1. GitHub 저장소 deka2026/solidarity-intelligence-wiki를 내 계정으로 Fork해줘 2. Fork한 저장소를 로컬에 clone해줘 3. 내 Quartz 위키의 content 폴더와 연대지능 위키의 wiki 폴더 구조를 비교해서 설명해줘 4. CLAUDE.md에 "연대위키에 올려줘"라고 하면 자동으로 문서를 작성하고 PR을 만드는 규칙을 추가해줘

개인 위키에서 문서 가져오기

개인 Quartz 위키에 이미 작성한 문서를 연대지능 위키 형식에 맞게 바꿔서 반영 요청을 해요.

내 위키에서 연대지능 위키로 문서를 올려줘. 내 위키 경로: [내 Quartz 위키 content 폴더 경로] 올릴 문서: [파일명 또는 주제] 연대지능 위키 템플릿(concept, field-note, how-to, case-study) 중 적합한 것을 골라서 온톨로지 분류(클래스, 인스턴스, 속성, 관계)를 적용한 뒤 PR을 만들어줘.

현장기록 바로 올리기

현장에서 경험한 것을 바로 연대지능 위키에 기록합니다. 개인 위키에 먼저 저장할 필요 없이 바로 반영 요청을 할 수 있어요.

연대위키에 올려줘. 오늘 [지역/마을 이름]에서 [활동 내용]을 했어. [참여자, 장소, 시간 등 기본 정보] [주요 내용, 논의 사항, 결정 사항] [느낀 점, 배운 것, 다음에 할 일]

개인 위키에 연대지능 위키 링크 연결

개인 Quartz 위키에서 연대지능 위키의 문서를 참조할 수 있도록 링크를 설정합니다.

내 Quartz 위키에서 연대지능 위키를 참조할 수 있게 설정해줘. 1. content/index.md에 연대지능 위키 링크 섹션을 추가해줘 - 연대지능 위키 GitHub: https://github.com/deka2026/solidarity-intelligence-wiki - 위키 문서 목록 링크 2. 내가 PR로 올린 문서에 대해 개인 위키에서 [[연대위키-제목]] 형태로 크로스 레퍼런스를 만들 수 있게 가이드해줘 3. 연대지능 위키의 새 문서가 올라오면 관련 내용을 내 위키에도 요약해서 남기는 습관을 만들어줘

기존 문서 최신 상태로 맞추기

연대지능 위키에 반영된 내 문서를 개인 위키에도 맞춰서, 양쪽에서 모두 확인할 수 있게 해요.

연대지능 위키와 내 개인 위키를 동기화해줘. 1. 내 Fork 저장소를 upstream(deka2026/solidarity-intelligence-wiki)과 sync해줘 2. 머지된 문서 중 내가 작성한 것을 확인해줘 gh pr list --repo deka2026/solidarity-intelligence-wiki --author @me --state merged 3. 머지된 문서를 내 Quartz 위키 content 폴더에도 복사해서 개인 위키에서도 볼 수 있게 해줘 4. 개인 위키에 "연대지능 위키 기여 목록" 페이지를 만들어서 내 기여 이력을 정리해줘

반영 요청 상태 확인

내가 올린 반영 요청의 상태를 확인하고, 검토 의견에 대응해요.

연대지능 위키에 올린 내 PR 상태를 확인해줘. gh pr list --repo deka2026/solidarity-intelligence-wiki --author @me --state all 리뷰 코멘트가 있으면 내용을 보여주고, 수정이 필요하면 반영해서 업데이트해줘.

동료 문서 검토하기

다른 활동가가 올린 문서를 검토하여 활동 점수를 쌓고 지식의 품질을 높여요.

연대지능 위키에 올라온 리뷰 대기 PR을 확인하고 리뷰해줘. gh pr list --repo deka2026/solidarity-intelligence-wiki --state open 1. 열린 PR 목록을 보여줘 2. 내가 리뷰할 PR 번호를 골라줄게 3. 온톨로지 5가지 질문(클래스 명확성, 속성 충분성, 관계 링크, 사실/의견 구분, 출처 명시)으로 리뷰 코멘트를 작성해줘 4. gh pr review로 코멘트를 제출해줘
